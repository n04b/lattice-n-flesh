# 01. Модель данных, история, файлы

## Единицы и оси

- Единица длины — **миллиметр**. STL экспортируется в мм.
- Правая система координат, **Y направлена вверх**. «Земля» — плоскость XZ.
- Углы в интерфейсе задаются в градусах. Поворот объекта применяется в порядке X → Y → Z, то есть матрица R = Rz·Ry·Rx. Обратный поворот: Rx⁻¹·Ry⁻¹·Rz⁻¹, применяется к точке в порядке Z, Y, X.

## Слой 1: рёбра

```
Edge { a: [x,y,z], b: [x,y,z] }
edges: Edge[]                 // порядок не важен
```

- Общих вершин нет. Два ребра «соединены», если их концы совпадают после округления.
- **Ключ точки:** `round(x·1e4), round(y·1e4), round(z·1e4)`, то есть точность 0,1 мкм. **Ключ ребра:** два ключа точек, упорядоченные лексикографически и соединённые через `|`.
- **Инвариант:** нет рёбер нулевой длины (короче 1e-4) и нет дубликатов по ключу ребра. Его обеспечивает единственная функция добавления `addEdges(list)`: она возвращает реально добавленные рёбра.
- Перемещение рёбер: выбранные удаляются, сдвинутые добавляются заново через `addEdges`, так что совпавшие со существующими сливаются.

## Слой 2: дерево объёмов

```
Shape {
  id: int, kind: 'shape', type: 'box'|'sphere'|'cyl'|'cone'|'torus'|'capsule'|'half',
  name: string, pos: [x,y,z], rot: [deg,deg,deg], dims: { ... }, hidden: bool, mod: Mod
}
Group {
  id: int, kind: 'group', name, op: 'folder'|'union'|'subtract'|'intersect',
  k: float /* скругление CSG, мм */, children: Node[], hidden: bool, mod: Mod
}
Mod { on: bool, thick: мм, blend: мм, fall: bool /* затухание к краю */, curve: 'smooth'|'linear'|'convex'|'concave',
      mode: 'max'|'add'|'sub' }
vols: Node[]                  // корень; порядок = порядок применения модификаторов
```

- Параметры `dims` по типам описаны в [04-volumes.md](04-volumes.md).
- Значения `id` уникальны. После загрузки счётчик выставляется в max(id) + 1.
- У группы нет собственного положения. Перемещение группы сдвигает всех её потомков.
- Поле `mod` есть у каждого узла, но действует только у **корня модификатора** (см. 04).

## История (undo/redo)

- Используются снимки: перед каждой изменяющей операцией весь документ `{e, v}` сериализуется в JSON и кладётся в стек undo. Глубина — 100 снимков. Любое новое действие очищает стек redo.
- Восстановление снимка сбрасывает выделение и текущую операцию инструмента.
- Если операция ничего не изменила (например, ребро уже существовало), последний снимок снимается со стека.
- При вводе в инспекторе в историю пишется один снимок на серию правок поля (от фокуса до ухода), а не на каждое нажатие клавиши.
- При переносе на большие сцены стоит перейти на журнал команд или разностные снимки.

## Автосохранение

Через 400 мс после изменения документ пишется в `localStorage['edge-editor']` в том же формате, что и снимок истории. Ошибки доступа к хранилищу игнорируются.

## Формат JSON (версия 2)

```json
{ "format": "edge-editor", "version": 2,
  "edges": [ [[x,y,z],[x,y,z]], ... ],
  "vols":  [ Node, ... ] }
```

Загрузчик также принимает версию 1 (без `vols`) и просто массив рёбер.

Миграция: в ранних файлах `mod.fall` было числом (мм затухания наружу). При загрузке нечисловое значение заменяется на `false`, неизвестная кривая (например, `step`) — на `smooth`.

## OBJ

- **Экспорт:** вершины дедуплицируются по ключу точки, каждое ребро записывается строкой `l i j`.
- **Импорт:** читаются `v`, `l` и `f`. Линия `l` с N вершинами даёт N−1 рёбер; грань `f` даёт замкнутый контур. Поддерживаются отрицательные индексы, а суффиксы `/vt/vn` отбрасываются.

## STL (результат)

Бинарный формат:
- заголовок — 80 байт;
- `uint32` — число треугольников;
- на каждый треугольник: нормаль (3 × `float32`), 3 вершины (9 × `float32`) и `uint16` = 0.

Порядок байт — little-endian. Нормаль вычисляется как нормированное векторное произведение (B−A)×(C−A). Обход вершин — против часовой стрелки, если смотреть снаружи.
